# Autonomous Baseline Edit

Use this when the user broadly asks to edit a Thai short-form clip and does not explicitly require approval before rendering.

## Inspect First

Before planning or rendering, inspect:

- **Audio**: duration, waveform, long silences, coughs, retakes, "เอาใหม่", loudness, clipping.
- **Speech**: transcript authority workflow, main idea, hook, offer/CTA, repeated or abandoned phrases.
- **Visuals**: contact sheet, face position, framing, existing captions/logos, blank zones for text, motion/gesture beats.
- **Files**: provided B-roll, images, product shots, music, brand fonts, required wording.

If the user provides only A-roll, still create a first cut. Treat B-roll as planned slots, not as a blocker.

## Plan Then Render

Create an edit intent plan before rendering. Keep it practical:

- Cut list: what gets removed and why.
- Opening headline: one short hook from the actual content.
- Subtitle approach: position, size, and any spelling/proper-noun fixes.
- Subtitle layout timeline: per-second/per-scene placement for headline, subtitle, keyword, face, and B-roll focus zones.
- Keyword emphasis: few important words only.
- Effects: punch-in, snap emphasis, smooth zoom, crop shift, freeze/hold, or split-screen only when motivated.
- B-roll slots: time range, what should appear, why it supports the spoken line, and whether it can wait for user assets.
- Audio: music bed, SFX moments if any, and volume target.

Unless approval was requested, continue into a baseline render after planning.

## Baseline First Cut Requirements

A usable first cut should include:

- speech-safe cleanup and retake removal;
- headline for the first 2-4 seconds unless the content starts better without one;
- readable Thai subtitles from the canonical transcript;
- Thai typography check for vowels and tone marks;
- keyword emphasis separated from subtitles;
- 3-6 motivated visual changes across a 30-60 second clip;
- light grade with natural skin tone;
- low-volume music bed when music is provided;
- contact sheet verification.

## B-roll Placeholder Policy

- Do not invent a real product demo, testimonial, before/after, medical proof, or financial result.
- If no B-roll assets exist, prefer:
  - face-safe keyword overlays;
  - simple labels;
  - zoom/punch/crop variation;
  - neutral icon/card placeholders only when they clearly read as placeholders.
- Save B-roll slots in the project log so the next pass can replace them quickly.

Suggested B-roll slot format:

```text
00:08.20-00:11.50 | spoken line: "..." | asset needed: product close-up | purpose: show proof/result | placement: top half/split/PiP
```

## Handoff

When returning the baseline edit, include:

- output path;
- short summary of cuts/effects/subtitles/music;
- B-roll slot plan for replacement;
- verification results and contact sheet path;
- any uncertain transcript phrase or missing asset.
